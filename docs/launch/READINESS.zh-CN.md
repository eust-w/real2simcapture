## 发布判断

2026-10-29 补充：[X 原生视频帖子](https://x.com/eustancewu/status/2115537584411873510) 已发布，公开页面、实际播放及中文字幕已核实；本次仅补发宣传介绍，不构成新的真机或引擎验收。

适合准备面向机器人开发者的开源开发预览。当前不具备以“完整实时高精度场景重建产品”对外首发的证据。“明星项目”是增长目标，不能保证 Star 数或传播结果。

建议定位：**从 iPhone 采集数据，到可检查、可编辑、可导出的机器人仿真资产。**

英文定位草案：**An iPhone-to-simulation capture and asset pipeline for robotics developers.**

已有工具覆盖手机采集到 NeRF/3DGS 的流程，例如 [Nerfstudio 的自定义数据文档](https://docs.nerf.studio/quickstart/custom_dataset.html)。因此本项目更有价值的切入点是尺度、视觉与碰撞几何、物理参数来源、格式导出和引擎验证的可复现工作流。这是产品定位判断，不是未经测评的竞品优越性结论。

## 本轮实施更新

- 已加入 ARKit 网格周期上传和 Web 实际 OBJ 三维刷新，使用真实网格快照；不承诺摄影级表面重建或固定时延。
- 上传改为有界顺序队列，积压帧在手机本地保留并于结束前补传。后端写入串行化、原子替换，非法网格保留上一有效版本，结束请求幂等。
- 修复 ARKit 深度与世界坐标到 z-up 的转换，并修复原生 mesh index buffer 读取。
- 新增五项 Live 回归测试，测试夹具不作为真机证据。
- 已生成独立核心依赖锁文件；新的核心环境与前端审计返回零已知漏洞，旧重型实验环境的漏洞记录没有因此消失。
- 新增中英文 README、安装/贡献/安全/第三方文档、GitHub CI 与问题模板。移除作者机器专用默认路径和组织包标识。
- Git 历史及暂存源码快照通过 Gitleaks 规则检查；这不是完整人工安全审计。
- 本机 Xcode 安装再次遇到 Apple 返回 HTML 而非 JSON，USB 未检测到 iPhone。没有完成真机验收或获得新真实采集录像。
- 本轮干净核心环境：55 项后端测试通过、1 项跳过、3 项外部检查单列；前端 5 项测试及生产构建通过。仍有 bundle 体积、几何和测试客户端告警。
- GitHub CI 的后端、前端、浏览器回归和无签名 iOS 真机目标编译均已通过，参见 [CI 记录](https://github.com/eust-w/real2simcapture/actions/runs/40305853599)。这不证明签名安装成功。

## 首次验证

- 前端：4 个测试通过，生产构建通过；有 bundle 体积告警。
- 后端：54 个测试通过，耗时 366.29 秒；5 条告警涉及 Starlette 测试客户端弃用及部分几何测试的体积计算。测试包含程序生成输入，不等于真机采集验收。
- `npm audit --json`：registry quick endpoint 返回 400，不能记为通过。
- 替代只读检查：向 npm registry bulk advisory endpoint 查询锁文件中的 253 个包，返回 Vite、Vitest、PostCSS 等版本的漏洞公告，包含 high 级别。仍需依赖更新和影响分析。
- 当前 Python 虚拟环境的 `pip-audit`：13 个包共 87 项已知漏洞记录。该环境包括可选重型依赖，这不是 87 个已证实可利用的项目漏洞；需要拆分基础环境/可选依赖后升级并复测。
- 本次没有运行真实 iPhone 采集，没有重新验证远端仿真主机，也没有测量扫描精度或端到端延迟。

## 首发范围

建议首个版本使用 `v0.1.0-alpha.1`，明确标注开发预览。首发只承诺经同一份真实采集数据验证的功能。

1. 一份可授权公开的桌面或小房间样例，保留 RGB、depth、pose、intrinsics 和来源说明。
2. 原生 iPhone 采集入口，给出实测机型、iOS、Xcode、签名和安装步骤。
3. Web 检查与资产导出，以 MuJoCo 作为首个需完整验收的路径；其他引擎标明验证状态与额外环境要求。
4. 输出视觉几何、碰撞几何、尺度和物理参数来源。质量、摩擦及材质估计必须区别于实际测量。
5. 能在第二台干净机器上复现的快速开始，不依赖作者的绝对路径或私有云账号。

若首发要以“边扫边构建”为主卖点，需要对本轮新增的 ARKit 网格快照链路完成真机验收，并记录长时间扫描的延迟、网络恢复和资源占用。代码与测试通过不能替代这一步。

## 社区与增长

首发内容围绕同一条可复现案例：实际场景、采集包、处理结果、引擎运行、失败边界。展示精度时说明标尺或测量方法；展示速度时说明硬件、输入规模、处理时间及是否加速播放。

优先关注外部用户能否完成第一次导入、安装阻塞数、有效问题反馈和外部贡献，而不是仅看 Star。发布后把真实问题拆成可贡献的小任务，例如特定机型兼容、坐标系测试、导出器、数据格式和文档翻译。

建议顺序：可复现 release 和 README -> B站/YouTube 完整视频 -> 抖音/小红书短片 -> 使用反馈和第二个场景案例。尚未安排自动发布或定时任务。
